I diagnosed the systematic Codex task failures:
- **Symptom:** Two tasks failed with identical 400 errors: `"The 'gpt-5.3-codex' model is not supported when using Codex with a ChatGPT subscription"`
- **Root cause:** The controller's `dispatcher.go` was injecting an environment variable `CODEX_MODEL=gpt-5.3-codex`, which is unsupported
- **Why it mattered:** Every Codex task queued since this was set would fail immediately before even starting

- Created `validCodexModels` map with known-good models (gpt-5.5, gpt-5.4, gpt-4o, etc.)

- Falls back to `gpt-5.5` if an unknown model is set, logging a warning
- This prevents future model migrations from silently landing on unsupported versions
